1. Usage                                                      *commits-usage*

A browser opens in a new tab, with the list of commits at the bottom and the
diff of a file above it.

:Commits [args]                                               *:Commits*
    Open the commits that `git log [args]` lists, like
    `:Commits main..HEAD --author=Joakim`.

The plugin sets no global keys. These functions open common lists:

require("commits").log()                                      *commits.log()*
    The last 100 commits.

require("commits").branch()                                *commits.branch()*
    The commits on this branch that origin's default branch doesn't have,
    oldest first.

require("commits").file()                                    *commits.file()*
    The commits that changed the current file.

require("commits").lines()                                  *commits.lines()*
    The commits that changed the selected lines. Map it in visual mode.

require("commits").open({args}, {opts})                      *commits.open()*
    The commits that `git log {args}` lists. {opts}.root is the repo, the
    current file's by default. {opts}.path, when set, is the only file each
    commit shows, for `git log -L`.

==============================================================================
2. Keys                                                        *commits-keys*

Each key calls a function on the module. Without an `on_attach` in
|commits-setup|, the list and the diff get these keys:

  Key         Function                Action ~
  <CR> o      commits.select()        On a commit in the list, show or hide
                                      its files. On a file, open its diff.
  ]c [c       commits.next_commit()   Next or previous commit, at its first
              commits.prev_commit()   file.
  ]f [f       commits.next_file()     Next or previous file of the commit,
              commits.prev_file()     wrapping around.
  ]h [h       commits.next_hunk()     Next or previous hunk in the diff.
              commits.prev_hunk()
  M           commits.message()       The full commit message, in the middle
                                      of the screen. q or <Esc> closes it.
  O           commits.browse()        The commit on the origin remote's web
                                      host, at the file's diff when on a file.
  P           commits.pull_request()  The commit's pull request on GitHub.
                                      Needs the GitHub CLI, gh.
  <leader>gd  commits.unified()       Switch to the unified diff.
  <leader>gD  commits.split()         Switch to the split diff.
  y           commits.copy()          Copy the commit's short hash, or
                                      hash:path on a file.
  q           commits.close()         Close the tab. Closing the list or a
                                      diff window with :q closes it too.

<CR>, o and y are in the list only. Each function acts on the browser the
current buffer belongs to, and does nothing outside one. commits.unified() and
commits.split() show a buffer's own changes outside a browser, see
|commits-unified|, so one global key can do both.

The unified diff shows the file as of the commit: added and changed lines
highlighted, removed lines shown above them, and unchanged lines folded. The
split diff shows the file before the commit on the left and the commit's file
on the right, in Neovim's diff mode.

The list reloads when a ref of the repo changes, like after a commit, a
rebase or a fetch.

==============================================================================
3. Setup                                                      *commits-setup*

setup() is optional. These are the defaults: >lua

    require("commits").setup({
      -- The diff a browser starts with: "unified" or "split".
      diff = "unified",
      -- Sets the browser's keys, see below.
      on_attach = nil,
    })
<
                                                          *commits-on_attach*
on_attach({buf}, {kind}) sets the browser's keys, as gitsigns' on_attach
does. The browser calls it for each buffer it shows: the list, with {kind}
"list", and each file the diff shows, with {kind} "diff". Set buffer-local
keys in it. The diff's files are real files, so the browser takes the keys
on_attach set off a file when the diff moves on from it. Without on_attach
the browser gets the keys in |commits-keys|. For example: >lua

    local commits = require("commits")
    commits.setup({
      on_attach = function(buf, kind)
        local opts = { buffer = buf, nowait = true }
        vim.keymap.set("n", "]c", commits.next_commit, opts)
        vim.keymap.set("n", "[c", commits.prev_commit, opts)
        vim.keymap.set("n", "M", commits.message, opts)
        vim.keymap.set("n", "q", commits.close, opts)
        if kind == "list" then
          vim.keymap.set("n", "<CR>", commits.select, opts)
        end
      end,
    })
<
Map the functions in |commits-usage| to open the browser, for example: >lua

    local commits = require("commits")
    vim.keymap.set("n", "<leader>gl", commits.log)
    vim.keymap.set("n", "<leader>gh", commits.file)
    vim.keymap.set("x", "<leader>gh", commits.lines)
    vim.keymap.set("n", "<leader>gm", commits.branch)
<
==============================================================================
4. The view worktree                                           *commits-view*

The diff shows the real file, checked out in a worktree of the repo at
`<git dir>/commits-view`, so language servers work in it as in any file. The
worktree is created the first time and kept. It shares the repo's objects, so
it needs no fetch. Its files are read-only. A file the commit deleted shows in
a scratch buffer instead.

The checkout's node_modules folders, up to three levels down, are linked into
the worktree, so imports resolve. They hold the checkout's installed packages,
not the commit's.

==============================================================================
5. Colors                                                    *commits-colors*

Each group is a default, so a color scheme or your config can set it.

  CommitsAdded       Added line counts and the A status. Added's text color.
  CommitsRemoved     Removed line counts and the D status.
  CommitsChanged     The M status.
  CommitsSelected    The selected file in the list. Links to Visual.
  CommitsAddLine     Added lines in the unified diff. Links to DiffAdd.
  CommitsChangeLine  Changed lines. Links to DiffChange.
  CommitsDeleteLine  Removed lines. Links to DiffDelete.

The split diff colors its sides with CommitsSplitAdd, CommitsSplitAddText,
CommitsSplitRemove and CommitsSplitRemoveText. They're mixed from the theme's
Added and Removed colors and set again when the color scheme changes.

==============================================================================
6. A buffer's changes                       *commits-unified* *commits-split*

Two toggles show the current buffer's uncommitted changes, the way the
browser shows a commit's. Both compare the buffer with the file as the index
has it, so staged changes don't show. A file git doesn't track yet shows all
its lines as added.

require("commits").unified()                              *commits.unified()*
    Highlight the added and changed lines and show the removed lines above
    them, as the browser's unified diff. Again hides them. The diff follows
    edits as you make them, and staging or a commit when git writes the
    index. It's per buffer. For example: >lua

    vim.keymap.set("n", "<leader>gd", require("commits").unified)
<
require("commits").split()                                  *commits.split()*
    Show the changes as a split diff, with the index's file on the left, as
    the browser's split diff. Again closes it. Edits to the buffer show as
    you make them. Staging doesn't, until the split opens again. For
    example: >lua

    vim.keymap.set("n", "<leader>gD", require("commits").split)
<
